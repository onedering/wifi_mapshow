# Code review: gaps vs expected behavior

Ниже перечислены проблемы, найденные при сравнении требований из `README.md` с текущей реализацией.

## Критичные проблемы

1. **Нет загрузки карты и JSON через UI**
   - В `MainActivity` отсутствуют обработчики выбора файлов (Storage Access Framework / ActivityResult API).
   - Методы `MainViewModel.setMap()` и `MainViewModel.setProject()` нигде не вызываются, поэтому исходные данные фактически не подгружаются.

2. **Карта не отображается**
   - В layout есть `ImageView` (`mapImage`), но в коде нет установки изображения в этот `ImageView`.
   - Пользовательский сценарий «открыть карту и открыть JSON» сейчас не реализован.

3. **Фильтры внизу экрана не подключены к логике**
   - Есть `Spinner` для канала и `Spinner` для сети, но в `MainActivity` они не инициализируются адаптерами и не обрабатывают выбор.
   - `MainViewModel.selectedChannelRange`, `selectedSsid`, `selectedBssid` не обновляются из UI.

4. **Некорректная модель фильтрации SSID/BSSID для описанного UX**
   - Требование подразумевает два режима списка: «все SSID (все BSSID)» и «SSID(BSSID)».
   - В текущем коде один `Spinner` (`networkSpinner`) и логика `when` в `filterNetworks()` не обеспечивают явного выбора такого режима.

5. **Точки рисуются в координатах экрана без привязки к масштабу карты**
   - `drawCircle(it.x, it.y, ...)` использует «сырые» координаты, но карта в `ImageView` должна отображаться с `fitCenter`.
   - При отличии размеров исходной карты от экрана точки будут смещены.

## Существенные проблемы

6. **Подпись точки не соответствует формулировке требования**
   - Сейчас выводится только выбранная сеть: `"RSSI dBm (SSID / chX)"`.
   - В требовании: показать выбранное значение и в скобках «весь набор значений» (минимум SSID/BSSID/Channel/RSSI/Encryption или аналогичный полный набор).

7. **Неполная/жёстко зашитая цветовая шкала**
   - `RssiColorUtil` использует фиксированные 4 цвета (green/yellow/orange/red), без привязки к «присланной шкале».
   - Нет конфигурируемости и валидации попадания в требуемый диапазон.

8. **Парсинг RSSI хрупкий**
   - `rssiRaw.replace(" dBm", "").toInt()` падает при лишних пробелах, другом регистре, пустом или нечисловом значении.
   - Нет fail-safe обработки ошибок формата JSON.

9. **Нет обработки ошибок загрузки JSON**
   - `JsonRepository.loadProject()` вызывает `error("Cannot open JSON")` при проблеме доступа.
   - Исключения парсинга не перехватываются и не показываются пользователю (Snackbar/Toast/диалог).

10. **Потенциальные артефакты при повторном "Показать"**
   - Перерисовка идёт через новый bitmap в `overlay.background`, но нет явного сброса состояния, контроля прозрачности и оптимизации памяти.
   - Для больших экранов это может приводить к лишним аллокациям и GC-паузам.

## Архитектурные и UX-риски

11. **Данные в `StateFlow` не наблюдаются UI**
   - В activity не используется сбор (`collect`) `points/mapUri`, поэтому реактивная архитектура заявлена, но не применена.

12. **Нельзя подтвердить соответствие диапазонам каналов из требований**
   - В коде нет готового enum/модели диапазонов: 2.4 (1–13), 5 (34–180), 6 (14–33), 6 (>180).
   - Риск ошибок в границах диапазона высокий.

13. **Не закрываются ресурсы чтения JSON**
   - `InputStreamReader` создаётся без `use {}`; это может оставлять открытые дескрипторы.

## Приоритет исправлений

1) Реализовать выбор карты/JSON и установку данных в `ViewModel`.
2) Подключить спиннеры и модель фильтров (включая режимы SSID/BSSID).
3) Нормализовать координаты точек относительно отображения карты (`ImageView` matrix/scale).
4) Добавить безопасный парсинг RSSI и обработку ошибок JSON.
5) Уточнить и внедрить точную цветовую шкалу + расширенную подпись точки.
