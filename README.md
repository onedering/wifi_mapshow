ОПИСАНИЕ РАЗРАБОТАННОГО МОБИЛЬНОГО ПРИЛОЖЕНИЯ «WI-FI MAPSHOW»

В соответствии с задачей проекта была выполнена разработка мобильного приложения для визуализации результатов ранее выполненного Wi‑Fi обследования.
Название приложения: WiFi MapShow.

Целевая аудитория: Wi‑Fi инженеры, системные администраторы и специалисты эксплуатации сети, которым необходимо анализировать покрытие по готовым JSON-выгрузкам и планам помещений.
1. Техническое задание (ТЗ) на разработку
Цель: создание инструмента для просмотра карты помещения и анализа уровня сигнала по точкам замеров на мобильном устройстве Android.
Функциональные требования:
1.	Загрузка данных проекта: открытие JSON-файла с точками измерений и списком сетей в каждой точке;
2.	Отображение параметров: для каждой точки вывод значения RSSI, номера канала, а также (в расширенном режиме) SSID, BSSID и типа шифрования;
3.	Карта помещения: загрузка изображения карты/плана и наложение маркеров измерений поверх изображения;
4.	Фильтрация данных: выбор диапазона каналов (2.4/5/6 ГГц и «Все каналы») и фильтра по сети (все SSID, SSID со всеми BSSID, конкретная пара SSID+BSSID);
5.	Безопасность: приложение работает с пользовательскими файлами через системный Storage Access Framework (OpenDocument) и использует persistable URI permissions для чтения выбранных ресурсов.
2. Архитектура и реализация
Приложение разработано на языке Kotlin в среде Android Studio.

Разработанное приложение построено на базе архитектурного паттерна MVVM (Model-View-ViewModel), что обеспечивает четкое разделение ответственности между компонентами системы. Весь исходный код разбит на логические пакеты (data, ui, util) и состоит из следующих ключевых файлов:
1. Пакет Data (Слой данных)
Этот слой отвечает за модели входных данных и загрузку JSON из внешнего источника.
•	Models.kt — файл, содержащий описания структур данных (Data Classes).
o	Отвечает за формализацию сущностей проекта. Включает корневую модель (ProjectRoot), точки измерений (ScanPoint) и модели сетей (WifiNetwork);
o	классы аннотированы библиотекой GSON (@SerializedName), что позволяет корректно читать JSON с полями вида "SSID", "BSSID" и "RSSI (dBm)".
•	JsonRepository.kt — класс доступа к данным JSON.
o	Отвечает за чтение файла через ContentResolver и десериализацию содержимого в объект ProjectRoot;
o	инкапсулирует работу с InputStream и InputStreamReader, обеспечивая единый вход для загрузки проектных данных.
2. Пакет UI (Слой представления)
Этот слой отвечает за отображение интерфейса и взаимодействие с пользователем.
•	MainViewModel.kt — компонент архитектуры Android Jetpack, управляющий состоянием экрана.
o	Отвечает за хранение текущего проекта: списка точек и URI карты, а также выбранных фильтров (диапазон каналов и тип фильтра сети);
o	формирует список опций для фильтрации и вычисляет итоговый набор точек для отрисовки (для каждой точки выбирается сеть с максимальным RSSI после применения фильтров).
•	MainActivity.kt — точка входа в приложение (Activity).
o	Отвечает за инициализацию интерфейса, выбор карты и JSON через системные диалоги, применение фильтров и запуск отрисовки;
o	выполняет динамическую отрисовку маркеров и подписей поверх карты (базовый и расширенный режимы), включая перенос длинных подписей и позиционирование с учетом размеров экрана.
3. Ресурсы и конфигурация
•	AndroidManifest.xml — дескриптор приложения.
o	Отвечает за регистрацию MainActivity и базовые параметры приложения (тема, label, backup settings);
o	не запрашивает сетевые/геолокационные runtime-разрешения, так как приложение работает с уже собранными данными из файлов.
•	activity_main.xml — файл верстки интерфейса.
o	Отвечает за визуальное расположение элементов управления: область карты с overlay-слоем, два Spinner-фильтра и набор кнопок действий;
o	интерфейс построен на LinearLayout + FrameLayout, где карта и слой маркеров отрисовываются раздельно.
•	RssiColorUtil.kt — утилита визуализации сигнала.
o	Отвечает за преобразование RSSI в цвет маркера на основе градиентной палитры от -85 до -30 dBm;
o	используется при отрисовке точек для наглядного отображения качества сигнала.

Для удобства анализа приложение поддерживает два режима отображения подписи точки: краткий (RSSI и канал) и полный (RSSI, канал, SSID, BSSID, Encryption), что ускоряет как обзор покрытия, так и детальную диагностику.
3. Описание интерфейса и сценариев работы

Режим карты
Данный режим используется для визуального анализа ранее собранного радиообследования.
1.	Пользователь нажимает «Открыть карту» и выбирает изображение плана помещения.
2.	Пользователь нажимает «Открыть JSON» и выбирает файл проекта с точками измерений.
3.	В нижней панели выбирается диапазон каналов и фильтр по сети.
4.	Пользователь нажимает «Показать основную» или «Показать всю», после чего точки отображаются цветными маркерами с подписями по выбранному режиму.
4. Реализация безопасности и настройки
В файле AndroidManifest.xml приложение не запрашивает чувствительные разрешения (Wi‑Fi/Location), так как выполняет только локальную визуализацию уже экспортированных данных:
•	Доступ к файлам выполняется через SAF (OpenDocument) и выданные системой URI permissions.
•	Чтение ресурсов ограничено выбранными пользователем документами (карта и JSON).

Работа с данными:

Приложение не хранит корпоративные данные на удаленных серверах и не выполняет сетевых операций; обработка JSON и рендер карты выполняются локально на устройстве. Выбор файлов реализован через системные механизмы Android, что соответствует практике минимизации доступа к пользовательским данным.
Исходный код проекта организован как Android Gradle-проект с модульной структурой (`app`) и покрыт unit-тестами для ViewModel и вспомогательной логики.
Заключение по разделу
Разработанное приложение «WiFi MapShow» реализует поставленную задачу визуального анализа Wi‑Fi обследований: позволяет загрузить карту и JSON-данные, отфильтровать сети по диапазону/идентификаторам и быстро оценить распределение сигнала по точкам на плане помещения.
